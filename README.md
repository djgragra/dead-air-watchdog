# Dead Air Watchdog

> **New in 26.11.4: a new audio engine.** The part that reads the sound cards and the streams and measures the level is now a separate native program written in Rust (`engine/`), instead of hidden browser windows. It does not depend on hidden browser windows any more, keeps measuring when the main window is closed or busy, plays a stream that arrives in bursts (some security programs and proxies hand audio over that way) without stalls, does not drop an input for the small glitches a sound card can report (a Dante Virtual Soundcard, for example), and starts and retries streams in a staggered, spread-out way. The window, settings, alerts, backup and monitoring hours are the ones you know: your settings are kept, and sound cards are found again by their name. New in the same release: **stations** (group the streams of one station, with its own colour and logo), the **Alerts** choice for each input (on, off, or only an AUDIO YES / AUDIO NO indicator), and on Linux a short note about the `libasound2` library. See the CHANGELOG.

Free desktop app (Windows / macOS / Linux) that listens around the clock to the computer's **sound card** and to **any number of Icecast / Shoutcast streams** at the same time (up to 32 inputs) and sends an alert by **email and/or Telegram** when the level stays below a threshold for longer than N seconds. It lives in the system tray, keeps a local event log (exportable) and charts the silences of the last 7, 14 or 30 days.

## Features

- **Inputs**: any mix of sound cards / audio interfaces and streams (MP3 / AAC / Ogg Vorbis / Opus URLs), up to 32 in total. Each sound-card input has its own device and its own pair of channels (1–2 by default, or 3–4 … up to 15–16) or one single channel (1 to 16, mono, with one meter), so several cards, or several pairs of the same card, can be monitored together; two cards with the same name are numbered, a device already chosen by another input is marked in the list, a saved device that is gone is shown as "not found" (it is never swapped for another card), and each input in Settings shows its level so you can tell which is which (every stream is read by the audio engine itself, so there is no limit of 10 streams per window and 6 per server: 24 streams from one server were measured together in the tests). Streams of one radio can be grouped in a **station** (one name, one logo, a featured stream; the view *By station* shows one tile for each, opened by a click and by itself when a stream is in dead air, in the dashboard, the compact view and the wall display). Each input has its own **name**, optional **logo**, threshold and alert time, a **yellow delay**, optional **frozen-audio alarm** and **monitoring hours**, can be **paused for maintenance**, and can have its **alerts off** (watched and logged, no message, outside the overall state) or be an **indicator** (only AUDIO YES / AUDIO NO); alert channels, alarm sound and heartbeat are shared. Inputs can be added, edited and removed while monitoring runs.
- **SNMP devices**: *Settings → Inputs → Add SNMP device* watches a network device (a **DEVA DB8000** audio switch has a preset; any device that gives a number over SNMP v2c works, for example an Orban with the OID of its MIB) instead of an audio signal: the app asks for the value every few seconds (read only), the input is *normal* while the value is in your list of normal values, an *alert* when it is anything else for the time you set, *offline* when the device does not answer. It can also take the **traps** the device sends (UDP port 1162 by default). The values can have names ("1 = Main, 2 = Aux, 3 = MP3"). Alerts, pauses, monitoring hours and the log are those of every input; there is no level meter.
- **Dashboard**: one big traffic light with the worst state of all inputs (green all OK, yellow a countdown is running, red dead air, grey stopped) and one tile per input with its state, countdown and live level meter (RMS per channel, peak hold, threshold marked).
- **Wall display** (clock and date as large as the screen allows, logos small / medium / large / as a soft background, names up to very large, every input from 1 to 32 is shown, the tiles rearrange to fit the screen; long names wrap on two lines and shrink to fit, or use a fixed size; the order is the one of the inputs in Settings, which you can change with ▲ ▼) for an always-on screen in a newsroom, studio or the technical manager's office: full screen, the screen kept awake, one large tile per input and a **glow around the screen edge** — green and slowly breathing while all is well, yellow while a countdown runs, flashing red during dead air (steady under *reduced motion*). The glow can also be shown in the normal window. The app can open straight into it.
- **Settings**: silence threshold (dBFS), minimum silence duration (seconds), alert channels, optional repeat while the alarm lasts.
- **Alerts**: SMTP email (several recipients in one field: **one message with everybody in Bcc**; with a user name the connection must be encrypted) Telegram (several recipients, each with a note) and **HTTP** (a request to an address you choose, POST with JSON or GET, for a studio screen or an automation), always naming the input, a desktop notification and an optional **alarm sound** on the computer: a single sound for all inputs (two-tone beeps with pauses), silenced with one button, re-armed by every new alarm, stopped when the last alarm ends. One alert when dead air starts, one when audio is back (with the duration). The **subject and text of each alert can be your own** (Settings → Alerts → Wording of the alerts, with `{input}`, `{cause}`, `{start}` … placeholders; empty = the text of the app). Failed deliveries are retried for up to 30 minutes, and the dashboard says when an alert could not be delivered (with the reason) until the next one goes through.
- **The alarm sound** calms down by itself and can be silenced without the window: *Continuous sound for N minutes, then one beep every M minutes* (0 = continuous until the alarm ends, as before); silence it from the tray icon, with a **global key combination** (for example `Ctrl+Alt+M`, also from a wireless remote) or, if you switch it on, from **Telegram** (`/silenzia` or `/mute`, only from the chats that receive the alerts). A new alarm starts the sound again. The *repeat* field (*Repeat the message every N minutes*) concerns only email, Telegram and HTTP messages.
- **Names and logos**: the name appears on the tile, in the alerts and in the log; the logo (PNG, JPG, WebP, GIF or SVG up to 5 MB, shrunk to 256 px) on the tile, also in the wall display. Logos are stored as small PNG files in the `logos` folder next to the settings and never leave the computer, except inside a configuration backup that you save yourself (0.2.1 and later: the backup file carries them, each once even if several inputs share it, and *Include the logos* can be switched off; a file from the public version has none). Inputs of the same station share one logo (*Use a logo already loaded…*).
- **Event log**: input, start, end, duration, cause (silence / input offline) and also the periods when nothing was monitored (app closed, computer asleep), the **pauses** and the **micro-silences**. Export to CSV and JSON.
- **Now playing**: for a stream, *Settings → Inputs → More options → Show the song title (now playing) on the tile* (off by default) shows the title the Icecast / Shoutcast server announces inside the stream (ICY metadata) under the state of the input, in the Dashboard, the compact view (while the input is OK) and the Wall display. One short extra request to the server every 20 seconds (a few KB, the audio read for it is discarded), only while monitoring and while the window is on screen; nothing is stored, and it never changes what is measured or when an alarm starts. Servers that send no titles show nothing.
- **Micro-silences**: every drop below the threshold, however short, is logged with time, duration and cause (silence, no data, late measurements), counted per input and in total for today, kept for 30 days by default. No alert is sent for them and the alarm rule does not change: they are there to tune the threshold, to tell a fault of the program from one of the stream or of the network, and to show data to whoever provides the stream. You can switch them off for all the inputs (Settings → General) or for one input (More options): then nothing is written, counted or shown for it, and the summary cannot use them to tell a stream fault from a network one.
- **Compact view and always on top**: a small window for a screen full of other programs, one row per input with its state and two thin level meters (smallest window about 280 × 110 px; the menu bar can be hidden in this view and comes back with a right-click; zoom with Ctrl + wheel); *Always on top* works in either view; both are remembered, with the place and size of each view; button at the bottom of the side bar and item in the tray menu.
- **Pause for maintenance**: a button on each tile switches off the alerts of that input for 1 hour or until tomorrow 06:00; it ends by itself, survives a restart and is written in the log. The input is still measured and shown as PAUSED.
- **Yellow after…** (per input, 2 s by default, 0 = as before): the traffic light of the input stays green until the audio has been below the threshold for that long, so the pauses of a speaker do not flash yellow, above all with many inputs on the wall display. Only the colour changes: the red alarm still counts from the first quiet moment, and an input that delivers no data turns yellow at once.
- **Monitoring hours** (per input, Settings → Inputs → More options): days and hours (also past midnight) in which the input is **not monitored** (no alarm, no alert, no sound; it is still measured and shown as PAUSED until the end of the window) or has **its own threshold and time before the alarm**. An alarm that is open when the hours begin is closed in the log without a "back" message; when they end the countdown starts again from there.
- **Frozen-audio alarm** (per input, off by default): the level stays within a small range (1 dB by default) for the time you set (at least 10 s) although it is above the threshold: a steady tone, a stuck loop or constant noise. It has its own cause in the log and in the alerts ("Frozen audio") and ends, with a "back" message, when the level moves again.
- **Summary and common problems** (Event log → Summary): per input the availability (share of the monitored time without dead air; the time the app was not running, pauses and hours switched off do not count), the number of alarms, the total and the longest dead air, for this month, last month or the last 7 / 30 days, with **CSV export**. When at least 3 inputs (or 2 when there are fewer, or 30% of them if that is lower) lose their data or go into alarm within 10 s of each other, the events are marked **Common problem** in the log (and in the CSV, column `common_problem`) and listed under the summary: the cause is probably the network or the computer that monitors, not the stream servers; the table also gives the availability without them.
- **Grouped alerts**: when several inputs fail (or come back) together, the first alert goes out at once and the others within the window (60 s by default) follow in one message with the list.
- **Chart** of dead air per day (7 / 14 / 30 days), for all inputs or one; the log can be filtered by input too.
- **Heartbeat** (optional): while monitoring, the app sends a plain GET to an address you choose every 1–60 minutes. A service that alerts when these requests stop (for example Healthchecks.io) then warns you when the computer is off or asleep, the app crashed or the network is down: things the app cannot report itself.
- **Runs unattended**: tray icon with status colour, start at login, keeps the computer awake while monitoring, automatic reconnection of devices and streams, restart of the audio engine if it stops responding.
- **Languages**: English (always the starting language), Italiano, Español. Dark theme by default, light and system available.
- **Backup of the configuration**: Settings → Configuration backup exports and imports inputs, thresholds, alerts, heartbeat and general settings as `dead-air-watchdog-backup-YYYY-MM-DD.json`. Passwords and tokens (email password, Telegram token, heartbeat address, user name and password inside a stream address) are **left out unless you tick “Include passwords and tokens”** (red warning, plain text, file readable only by you where the system allows it). Import: replace everything, or add only the inputs the computer does not have; then the app lists what must be typed again. The event log and the “already told” flags are not part of the backup.
- **Guided updates**: the app checks the public GitHub releases and shows a banner with *Download and install*, *Remind me later*, *Skip this version* and the release notes; the download has a progress bar and a *Cancel* button and is verified against `SHA256SUMS.txt` (SHA-256); *Close and install* asks first (monitoring stops), makes a safety copy of the settings, starts the installer (Windows), opens the disk image (macOS) or shows the AppImage (Linux); after the update a *What's new* window lists the changes. Nothing is installed without a click. If email or Telegram is on, the app also tells you **once per version and per channel** that a new version is out (switch off with “Tell me by email or Telegram…” in Settings → Updates); a channel counts as told only after the message was delivered, and what was told survives restarts (`alert-state.json`).

- **Help & about**: *Copy support info* (version, system, last check, last error: never settings, addresses or passwords), *Open logs folder*, installation name shown in the alerts, log files per day (7 days, 5 MB each), the window remembers its place and size, a show/hide button on passwords.

## Install

Download the installer for your system from the [Releases](https://github.com/djgragra/dead-air-watchdog/releases) page and verify it against `SHA256SUMS.txt`. The app is free and **not code-signed**:

The **user manual** is attached to every release as three PDFs: English (`Dead-Air-Watchdog-Manual-EN-<version>.pdf`), Italian (`-IT-`) and Spanish (`-ES-`). Its source is in `docs/manual/` (`python3 docs/manual/build.py <version> <folder>` makes the PDFs; it needs Chrome or Chromium).

- **macOS**: the app is signed ad hoc (no Apple account), so the first start says "unidentified developer": open *System Settings → Privacy & Security*, scroll down and click *Open Anyway* (tested on an Apple Silicon Mac from 26.10.9; earlier versions said "damaged"). **Second method**, in Terminal: `xattr -cr "/Applications/Dead Air Watchdog.app" && codesign --force --deep -s - "/Applications/Dead Air Watchdog.app"` (it also opens an earlier version that says "damaged"; change the name to open another OnAir Garage app).
- **Windows**: if SmartScreen appears, click *More info* → *Run anyway*.
- **Linux**: install the system libraries first: **libasound2** (the audio engine is linked to it, even for streams only) and FUSE for AppImages: Debian/Ubuntu `sudo apt install libasound2 libfuse2` (Ubuntu 24.04, Debian 13: `libasound2t64 libfuse2t64`), Fedora `sudo dnf install alsa-lib fuse-libs`, Arch `sudo pacman -S alsa-lib fuse2`. Then `chmod +x Dead-Air-Watchdog-*.AppImage` and run it. On Debian/Ubuntu you can use the **.deb** instead: `sudo apt install ./Dead-Air-Watchdog-<version>.deb` (it installs the libraries it needs, no FUSE). "Start with the computer" writes `~/.config/autostart/dead-air-watchdog.desktop`. Without libasound2 the app opens and a red banner explains it.

### Why it asks for the microphone

Operating systems treat every audio input (sound card, interface, USB mixer) as a "microphone", so the permission prompt is the same. The app only measures the level ten times per second. It does **not** record, store, play back or send audio. The input is opened with automatic gain, noise suppression and echo cancellation switched off so that the measured level is the real one. Monitoring a stream URL needs no permission.

## How it works

Every 100 ms the audio engine (a separate program written in Rust, so it keeps running when the main window is closed) measures the RMS level of each channel (and the peak): `10·log10(mean(x²))`, samples in −1…+1, result in **dBFS**. A full-scale sine reads −3.01 dBFS, a full-scale square wave 0 dBFS. The loudest channel is compared with the threshold; **silence means all channels are below it**.

- Below the threshold → *counting* (yellow). When it lasts at least the configured time → *alarm* (red), alert sent. The silence is dated from its first quiet sample.
- Audio is *back* only after it stays at or above the threshold for **2 s in a row, or 2 s in total within 5 s**: one click in a silent stretch does not restart the countdown, and speech, with pauses below the threshold between the words, counts as audio (before 26.10.8 it could raise a false alarm after the alert time even though somebody was talking).
- If the input delivers nothing (device removed, stream down, engine stalled, no level report for 1.5 s) this counts as dead air with cause **offline**.
- If the process does not run for more than 10 s (sleep, freeze) the countdown is dropped and the period is logged as a monitoring gap.

## Assumptions and limits

- Not a certified instrument. The level is a plain RMS value, **not** a loudness (no K-weighting, no gating).
- Each stream is an extra listener on its server and an extra decoder in the app (light for MP3/AAC); several sound cards can be monitored, each input measures one pair of channels or one single channel (add one input per pair or channel), and every open card is one more capture in the system: the limit is the 32 inputs of the app. Opening more than one card, channel selection and the alarm sound could not be tried with real hardware (a card in exclusive use by another program on Windows cannot be opened; the input then reports it). The list of channels of an input shows only those the card really has (the card is opened briefly to count them). Pairs and channels beyond 15–16 / 16 are not offered; above 8 channels the device was not tried (if it delivers fewer channels than asked, the input reports a problem).
- The key combination that silences the sound is a global shortcut of the system: another program may already use it, and on Linux with Wayland it may not work; Telegram commands make the app ask Telegram for new messages every 5 seconds and must not be switched on for a bot that another program already reads (or that has a webhook); Telegram commands were tried only against a stand-in Telegram; the sound itself (continuous, calm, silenced) was run in the real app on Linux under a virtual screen, not on Windows or macOS. The alarm sound plays on the default output. With a microphone input near the speakers the beeps could be picked up; the pauses between bursts (0.36 s of sound, 0.84 s of silence) keep them from being read as returning audio, but a line input is safer.
- SNMP inputs: SNMP v1/v2c only (the community travels unencrypted: use it on your own network or a VPN, never over the open internet), one numeric value per input, the app never writes to a device. The DEVA DB8000 input preset follows the device's MIB; with its silence detector on, the manual says the device answers 0 to 3, so the value that means "normal" must be checked on the real device (on Main it was 1). Tried against a simulated device and on a real DEVA DB8000 (polling, traps, the alert on the tile, the email alert and the mail when it is back to normal; Main = 1, Aux = 2, MP3 = 3); Telegram and an Orban not yet.
- A stream is heard like any listener: it shows in the server's listener statistics, it arrives delayed by the stream's buffer, and if the server plays a fallback or filler when the source drops, the monitor sees that audio, not silence.
- HLS (`.m3u8`) streams are not supported by this tool. Shoutcast (ICY) servers and servers with redirects were not tested for the audio; the song title (ICY metadata) was tested against a local server that speaks the ICY protocol, not against real Icecast or Shoutcast servers.
- While the computer is asleep or switched off, or the app is closed, nothing is monitored and no alert can be sent. The app cannot warn you that the computer itself is down: that is what the heartbeat is for. It is an extra request to an address of your choice, sends no data besides the request and a User-Agent, and its address (usually a secret token) is stored encrypted when the keystore is available.
- Email, Telegram and HTTP-alert credentials (the address and the header) are stored in the app's data folder, encrypted with the system keystore (Keychain / DPAPI / libsecret) when available, in clear otherwise. They are only ever sent to your own mail server, to `api.telegram.org` and to the HTTP address you set. A backup written with “Include passwords and tokens” holds them in **plain text**; a sealed value cannot be read on another computer or user account, so a backup never carries it (the app asks to type it again).
- A new-version notice needs the app to be running when the check happens (at start and every 24 hours); machines left on an older version without this feature cannot announce anything until they are updated by hand.

## Run locally

Requires [Node.js](https://nodejs.org) 20+ and Rust ([rustup.rs](https://rustup.rs); on Linux also `libasound2-dev`).

```bash
npm install
npm run engine   # cargo build --release of engine/
npm start
```

Tests: `cargo test --manifest-path engine/Cargo.toml` and `npm test` (the Node tests start the engine and use ffmpeg for the stream tests). Installers (output in `release/`): `npm run dist:win`, `npm run dist:mac`, `npm run dist:linux`. Releases are built by GitHub Actions when a `v*` tag is pushed. Icons are generated by `python3 dev/make-icons.py`. Screenshots: `node dev/make-screenshots.mjs` (needs Playwright with Chromium; not a dependency of the app).

## Structure

- `main.js`, `preload.cjs`, `sound-preload.cjs` — Electron main process and bridges.
- `engine/` — the audio engine, in Rust: `src/capture.rs` (sound cards, `cpal`), `src/stream.rs` (HTTP streams, `ureq` and `symphonia`, paced at real time), `src/level.rs`, `src/engine.rs`, `src/protocol.rs` (one JSON object per line on stdin and stdout, protocol 2: `sync`, `stop`, `list_devices`; `levels`, `fault`, `ok`). The engine only measures; the detector, the monitoring hours, the frozen-audio alarm and the pauses are in `src/monitor.js` and `src/core/`, as before.
- `src/snmp.js` (SNMP inputs: polling and traps, `net-snmp`), `src/core/snmp-address.js` (the address, the OID and the normal values; also used by the window).
- `src/engine-client.js` (starts the engine and keeps it alive), `src/engine-bridge.js` (what the monitor sees as the engine), `src/devices.js` (sound cards: the ids and the names).
- `src/core/` — pure logic: detector state machine, frozen-audio detector, monitoring hours, availability report and common problems, level conversions, statistics, export, formatting.
- `src/` — store (settings, log), secrets (the one list of secret places), backup, alert-state, update-notice, addresses, logos, monitor (orchestration), heartbeat, notifications, updater, messages.
- `renderer/` — the window (`index.html`, `app.js`, `i18n.js`, `style.css`) and the hidden window that plays the alarm sound (`sound.html`, `sound.js`).
- `dev/` — tests, the synthetic stream server, the icon generator and the screenshot script.

Settings and the event log are in the OS user-data folder (`alert-state.json`, what the alerts already said, sits next to them) (`~/Library/Application Support/Dead Air Watchdog` on macOS, `%APPDATA%\Dead Air Watchdog` on Windows, `~/.config/Dead Air Watchdog` on Linux).

## Italiano

App gratuita che ascolta giorno e notte un ingresso audio del computer o uno stream Icecast/Shoutcast e invia un avviso via email e/o Telegram se il livello resta sotto soglia per più di N secondi. Registro eventi locale esportabile, grafico dei silenzi a 7/14/30 giorni, riepilogo con la disponibilità per ingresso (anche in CSV) e segnalazione dei problemi comuni (più ingressi giù insieme: probabile problema di rete o del computer). Giallo con ritardo, orari di monitoraggio e allarme per audio bloccato, per ogni ingresso. Dashboard e Wall display per uno schermo sempre acceso. Per gli stream, facoltativo: il titolo del brano (now playing) sulla tile, nella Dashboard, nella vista compatta e nel Wall display. Più destinatari email in un solo messaggio (tutti in Bcc), backup della configurazione (password e token esclusi di default) e avviso su email/Telegram quando esce una nuova versione. L'app non è firmata: su macOS usa clic destro → Apri; su Windows SmartScreen → «Ulteriori informazioni» → «Esegui comunque». Non è uno strumento certificato.
